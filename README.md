# pango-groupware

> Rust와 SQLite로 만드는 **가볍고 직접 설치해 쓰는(self-hosted) 사내 그룹웨어**
> 출퇴근 · 근태 · 휴가 · 전자결재 · 공지사항을 하나의 바이너리로.

[팡고지와이](https://github.com/pango-gy)에서 실제로 쓰려고 만들고 있으며, 같은 고민을 하는 다른 조직도 쓸 수 있도록 오픈소스로 공개합니다.

> [!WARNING]
> **개발 초기 단계(pre-alpha)입니다.** MVP를 만들고 있으며, API·DB 스키마는 예고 없이 바뀔 수 있습니다. 실제 업무에 쓰기 전에 직접 검증해 주세요.

## 왜 만드나요

소규모 조직에 필요한 것은 회계·재고·생산까지 다루는 무거운 ERP가 아니라, 매일 쓰는 **근태와 결재**입니다. 기존 SaaS 그룹웨어는 사용자 수만큼 비용이 늘고, 데이터가 외부에 있으며, 필요 없는 기능이 많습니다.

pango-groupware는 다음을 목표로 합니다.

- **작은 서버 한 대**(또는 저사양 VM)에서 충분히 돌아갈 것
- **설치가 간단할 것**: 실행 파일 하나 + SQLite 파일 하나
- **데이터를 조직이 직접 소유**할 것
- 한국 회사의 업무 방식(결재라인, 연차, 반차 등)을 기본으로 지원할 것

## 기능

### 구성원

| 영역 | 기능 |
| --- | --- |
| 출퇴근 | 출근·퇴근 기록, 외근·재택 표시, 위치/사내 Wi-Fi 기반 확인(선택) |
| 근태 | 월별 근무 기록 조회, 지각·조퇴·누락 확인, 기록 정정 요청 |
| 휴가 | 연차·반차·반반차·경조사 등 휴가 신청, 잔여 연차 조회 |
| 전자결재 | 문서 기안, 결재라인 지정(결재·합의·참조), 승인·반려·회수, 결재 대기함, 첨부파일 |
| 공지사항 | 공지 열람, 필독 공지 확인 표시, 첨부파일 |
| 알림 | 결재 요청·결과, 공지, 퇴근 누락 알림, 외부 연동(서명한 웹훅, 사내 메신저 Buzz DM — [운영 가이드](docs/BUZZ.md)) |
| AI 연결 | Claude 같은 AI 앱에서 대화로 휴가 신청·결재 기안·승인·공지 게시(원격 MCP + OAuth — [연결 매뉴얼](docs/MCP.md)) |

### 관리자

| 영역 | 기능 |
| --- | --- |
| 구성원 관리 | 계정 발급·비활성화, 부서·직급·역할 관리, 비밀번호 초기화 |
| 근태 관리 | 전체 출퇴근 기록 조회·수정(수정 이력 보존), CSV 내보내기 |
| 근무 정책 | 근무 시간·유연근무·휴게시간, 공휴일, 출퇴근 확인 방식 설정 |
| 휴가 정책 | 연차 자동 부여 규칙, 휴가 종류, 수동 조정 |
| 결재 관리 | 문서 양식 관리, 기본 결재라인 템플릿, 결재 현황 조회 |
| 감사 로그 | 관리자 작업·권한 변경·기록 수정 이력 |

## 설계 원칙

1. **가벼움 우선** — 의존성과 런타임을 최소화합니다. 기능 추가보다 유지 비용을 먼저 따집니다.
2. **단일 바이너리** — 서버, 웹 UI, DB 마이그레이션이 실행 파일 하나에 들어갑니다.
3. **SQLite** — 별도 DB 서버 없이 파일 하나로 운영합니다. 수백 명 규모의 사내 서비스에는 충분합니다.
4. **권한은 서버에서** — 모든 요청마다 대상 자원에 대한 권한을 서버가 확인합니다. 클라이언트의 화면 숨김에 의존하지 않습니다.
5. **기록은 지우지 않고 고친다** — 출퇴근·결재 기록의 수정은 원본과 변경 이력을 함께 남깁니다.

## 기술 스택

가능한 모든 부분을 Rust로 작성합니다.

| 계층 | 선택 | 비고 |
| --- | --- | --- |
| 서버 | [axum](https://github.com/tokio-rs/axum) + [tokio](https://tokio.rs) | REST/JSON API |
| DB | SQLite + [sqlx](https://github.com/launchbadge/sqlx) | WAL 모드, 쓰기 연결 1개 + 읽기 풀, 내장 마이그레이션 |
| 웹 UI | [Dioxus](https://dioxuslabs.com) | Rust → WASM. 서버 실행 파일에 포함 |
| 모바일 | Dioxus mobile (iOS/Android) | 웹과 같은 UI 코드를 네이티브 Rust + 시스템 WebView로 실행. 빌드 방법은 [개발 문서](docs/DEVELOPMENT.md#iosandroid-앱) |
| 비밀번호 | Argon2id | |
| 휴대폰 알림 | 사내 메신저 Buzz DM | 앱 자체 푸시(APNs·FCM)와 푸시 중계 서버는 두지 않습니다 |

데스크톱 앱은 만들지 않습니다. PC에서는 웹 브라우저로 사용합니다.

화면 구성은 [flex](https://flex.team)의 정보 구조(카드형 홈, 큰 출퇴근 버튼, 결재함 탭)를 참고했습니다. 데스크톱은 좌측 사이드바, 모바일은 하단 탭입니다.

## 저장소 구조

```text
pango-groupware/
├── crates/
│   ├── core/      # 도메인 타입과 순수 규칙 (근태·연차·결재 상태 전이·권한). IO 없음
│   ├── api/       # 요청/응답 타입. 서버와 웹이 함께 사용
│   ├── db/        # SQLite 스키마, 마이그레이션, 저장소
│   ├── server/    # 유스케이스 + HTTP + 실행 파일
│   └── web/       # 웹 UI (Dioxus, WASM)
├── xtask/         # 개발 작업 (웹 번들 빌드)
└── docs/          # 설계 문서
```

설계는 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), 기능 추가 방법은 [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)에 있습니다.

## 시작하기

Rust 1.85 이상이 필요합니다.

```bash
# 1. 웹 UI 빌드 도구 (최초 1회)
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.130 --locked

# 2. 웹 UI 번들 → 서버 빌드 (번들은 실행 파일에 포함됩니다)
cargo xtask web
cargo build --release -p pango-server

# 3. 최초 설정: 회사 정보와 최고 관리자 계정 생성 (임시 비밀번호가 한 번 출력됩니다)
./target/release/pango-groupware --data-dir ./data init --company "우리 회사"

# 4. 실행
./target/release/pango-groupware --data-dir ./data serve --bind 127.0.0.1:8080
```

HTTPS 없이 로컬에서만 써 볼 때는 `serve`에 `--insecure-cookies`를 붙입니다. 리버스 프록시 뒤에서 실행하면 `--trust-proxy`를 붙여야 접속 IP가 올바르게 기록됩니다.

### 운영 시 권장 사항

- 앞단에 TLS를 처리하는 리버스 프록시(Caddy, nginx 등)를 둡니다. 모바일 앱은 HTTPS 서버에만 연결합니다.
- 백업은 `pango-groupware --data-dir ./data backup <사본 경로>`로 실행 중에도 안전하게 만듭니다(첨부파일 포함). 서버가 실행 중일 때 DB 파일을 그대로 복사하지 마세요.
- Docker 이미지, systemd, 리버스 프록시, 백업·복구, 판올림은 [docs/DEPLOY.md](docs/DEPLOY.md)를 봅니다.
- Claude 등 AI 앱 연결(원격 MCP)은 `--mcp`로 켭니다. [docs/MCP.md](docs/MCP.md)를 봅니다.

## 모바일 앱 배포

사내용 앱은 일반 앱보다 배포 경로가 제한적입니다. 그리고 이 프로젝트는 **각 조직이 서버를 직접 설치**하는 오픈소스이므로, "한 회사의 사내 앱"과는 다른 제약이 추가로 생깁니다.

### iOS

| 방식 | 비용 | 특징 | 적합성 |
| --- | --- | --- | --- |
| **App Store 공개 배포** | 개발자 계정 연 $99 | App Review 필수. 로그인 앱은 심사용 데모 계정·서버 제공 필요 | ◎ 오픈소스 공식 앱에 적합 |
| **Unlisted 배포** | 연 $99 | App Store에 노출되지 않고 링크로만 설치. 심사는 동일 | ○ |
| **Custom App (Apple Business Manager)** | 연 $99 | 지정한 조직에만 비공개 배포. 조직은 ABM 가입(D-U-N-S 번호) 필요. MDM으로 일괄 설치 가능 | ○ 특정 회사 전용 빌드 |
| **Apple Developer Enterprise Program** | 연 $299 | 심사 없이 사내 직접 배포. 단, 100명 이상 법인 등 자격 요건이 엄격하고 신규 승인이 매우 어려움. 인증서 매년 갱신 | △ 비권장 |
| **TestFlight** | 연 $99 | 빌드가 90일 후 만료 | 테스트 전용 |
| **Ad Hoc** | 연 $99 | 기기 UDID를 등록해야 하며 기기 종류별 연 100대 제한 | 테스트 전용 |

### Android

| 방식 | 특징 | 적합성 |
| --- | --- | --- |
| **Google Play 공개 배포** | 심사 있음. 2023년 11월 이후 만든 **개인** 개발자 계정은 프로덕션 출시 전 12명 이상·14일 비공개 테스트가 필요(조직 계정은 면제) | ◎ 오픈소스 공식 앱 |
| **Managed Google Play 비공개 앱** | 지정한 조직(Android Enterprise / EMM 사용)에만 배포 | ○ 특정 회사 전용 빌드 |
| **APK 직접 배포(사이드로딩)** | 가장 간단. 단, Google이 인증 기기에서 설치되는 앱에 대해 **개발자 신원 확인 의무화**를 단계적으로 도입 중(2026년 일부 국가부터, 이후 전 세계 확대 예정)이라 향후 제약이 생길 수 있음 | △ 최신 정책 확인 필요 |

### 셀프호스팅 오픈소스라서 생기는 제약

공식 앱 하나를 스토어에 올리고 사용자가 **자기 회사 서버 주소를 입력**하는 방식(Mattermost, Rocket.Chat 등과 같은 방식)을 기본으로 합니다. 이 방식에는 다음 제약이 있습니다.

- **푸시 알림**: APNs·FCM 발송 키는 앱 배포자에게 묶여 있어, 각 회사 서버가 공식 앱으로 직접 푸시를 보내려면 푸시 중계 서버가 필요합니다. 이 프로젝트는 중계 서버를 두지 않고, 휴대폰 알림은 사내 메신저 **Buzz DM**으로 보냅니다([docs/BUZZ.md](docs/BUZZ.md)).
- **패스키 / Universal Links / App Links**: 앱에 미리 등록된 도메인에서만 동작합니다. 회사마다 도메인이 다른 셀프호스팅 환경에서는 공식 앱이 이를 지원할 수 없습니다.
- **App Review**: 심사용 데모 서버와 데모 계정을 프로젝트가 상시 운영해야 합니다.

위 기능이 반드시 필요한 조직은 **자체 빌드**(자기 번들 ID·푸시 키·도메인으로 빌드해 Custom App 또는 Managed Google Play로 배포)를 선택할 수 있도록 빌드 설정을 분리합니다.

> 앱 설치 없이 쓰고 싶다면 웹 UI를 PWA로 홈 화면에 추가할 수 있습니다. iOS는 16.4 이상에서 홈 화면에 추가한 경우에만 웹 푸시를 받을 수 있습니다.

## 인증과 로그인

### 기본 방식

- **회원가입 없음**: 계정은 관리자만 발급합니다. 앱에서 계정을 만들 수 없으므로 스토어의 "앱 내 계정 삭제 기능" 요구사항(App Store 5.1.1(v), Google Play 계정 삭제 정책)의 적용 범위가 줄어듭니다. 최종 판단은 제출 시점의 정책을 확인합니다.
- **아이디/비밀번호**: 비밀번호는 Argon2id로 저장합니다. 로그인 시도는 IP와 아이디별로 제한하며, 실패 응답으로 계정 존재 여부를 알 수 없게 합니다.
- **2단계 인증(TOTP)**: 구성원이 내 정보에서 켜면 로그인할 때 인증 앱의 6자리 코드(또는 한 번씩 쓰는 복구 코드)가 더 필요합니다. 휴대폰을 잃어버리면 관리자가 초기화합니다. SSO(OIDC)는 이후에 추가할 예정입니다.

### 모바일 로그인 시 지켜야 할 것

- **SSO는 시스템 브라우저로**: iOS는 `ASWebAuthenticationSession`, Android는 Custom Tabs를 사용하고 PKCE를 적용합니다. Google은 앱 내 WebView에서의 OAuth 로그인을 차단합니다.
- **Sign in with Apple**: Google·Kakao 등 **제3자 소셜 로그인**을 넣으면 Sign in with Apple도 함께 제공해야 합니다. 단, 회사 자체 계정이나 기업용 계정으로만 로그인하는 앱은 예외입니다. 이 프로젝트는 소셜 로그인을 제공하지 않을 계획입니다.
- **세션 토큰**: 서버가 발급하는 무작위 토큰을 쓰고, 서버에는 해시만 저장합니다. 웹은 HttpOnly 쿠키로, 모바일은 iOS Keychain / Android Keystore에 저장합니다. 유휴 14일·절대 90일에 만료되며 서버에서 즉시 폐기할 수 있습니다.
- **기기 관리**: 관리자가 구성원의 로그인 기기를 확인하고 하나씩 또는 모두 원격으로 세션을 끊을 수 있습니다(관리 → 구성원). 퇴사자 계정은 비활성화 즉시 모든 세션이 무효화됩니다.
- **생체 인증**: 앱 재실행 시 Face ID / 지문으로 잠금을 해제하는 기능(선택)은 저장된 토큰을 꺼내는 용도로만 쓰며, 서버 인증을 대신하지 않습니다.

## 개인정보와 법적 고려사항

출퇴근 기록은 **근로자의 개인정보이자 법적 근거 자료**입니다. 다음은 설계 시 고려하는 사항이며, 실제 도입 전에는 각 조직이 법률 검토를 해야 합니다.

- **위치 정보**: 출퇴근 확인에 GPS를 쓰면 개인위치정보 수집에 해당할 수 있습니다(「위치정보의 보호 및 이용 등에 관한 법률」). 기본값은 위치를 쓰지 않으며, 사용 시에도 **출퇴근 버튼을 누르는 순간에만** 확인하고 백그라운드 위치 추적은 하지 않습니다. 저장은 "사내 반경 내 여부" 결과만 남기는 것을 기본으로 합니다.
- **사내 Wi-Fi 확인**: iOS는 Wi-Fi 이름(SSID)을 읽으려면 별도 권한(Access Wi-Fi Information)과 위치 권한이 필요하고, Android도 위치 권한이 필요합니다.
- **보존 기간**: 근로기준법은 근로계약에 관한 중요한 서류를 3년간 보존하도록 정하고 있습니다. 최고 관리자가 **관리 → 근무 정책 → 기록 보존 기간**에서 출퇴근 기록의 보존 연수(3~10년, 기본은 지우지 않음)를 정하면, 지난 근무일의 기록과 수정 이력을 하루 한 번 지웁니다. 휴가 원장은 잔여 계산의 근거라서, 결재 문서는 그 자체가 결재 기록이라서 지우지 않습니다.
- **최소 수집**: 업무에 필요하지 않은 개인정보(주민등록번호 등)는 저장하지 않습니다.
